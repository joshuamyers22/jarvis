# Data ownership contract

> Generated from `config/data-ownership.toml`. Edit the manifest and run `make ownership-render`; do not edit this file directly.

Provider-neutral ownership and access expectations for Jarvis research data.

Contract ID: `jarvis-default`  
Schema version: `1`  
Review cycle: every 180 days  
Contract owner: `platform`  
Change approvers: `platform`, `data_governance`  
Exception process: [docs/storage-classes.md#exceptions](../docs/storage-classes.md#exceptions)

## Accountable groups

Group IDs are stable policy references. Deployments may change their display names and contact routes without changing workload identities or object prefixes.

| Group ID | Display name | Contact | Responsibility |
|---|---|---|---|
| `platform` | Platform owners | `team:platform-owners` | Storage infrastructure, runtime access enforcement, and recovery operations. |
| `source_data` | Source data owners | `team:source-data-owners` | Source licensing, ingestion approval, quality, and replay authority. |
| `research` | Research data owners | `team:research-data-owners` | Derived datasets, published artifacts, and acceptable research use. |
| `data_governance` | Data governance reviewers | `team:data-governance` | Classification, quarantine decisions, exceptions, and retention review. |

## Access actors

These are logical identities mapped to provider-specific service accounts or roles by Terraform. Human owners approve policy; workloads receive data-plane access.

| Actor | Kind | Identity contract | Access semantics |
|---|---|---|---|
| `control` — Airflow control workload | `workload` | `storage_contract.airflow_logs.workload_access.control` | Read and write only the Airflow log boundary. |
| `feed` — Feed ingestion workload | `workload` | `storage_contract.data.workload_access.feed` | Create ingestion objects; use immutable names where the provider cannot enforce create-only access. |
| `job` — Batch job workload | `workload` | `storage_contract.data.workload_access.job` | Read and write approved durable-data prefixes and scratch. |
| `notebook` — Interactive notebook workload | `workload` | `storage_contract.data.workload_access.notebook` | Read durable research data and read or write scratch. |
| `recovery` — Non-production recovery automation | `automation` | `recovery_contract` | Create immutable evidence in non-production; disabled in production. |

## Class details

### Raw source data (`raw`)

- Classification: `restricted`
- Accountable owner: `source_data`; operational steward: `data_governance`
- Writers: `feed`, `job`; readers: `job`, `notebook`
- Retention policy: `retain-current` — Never automatically delete current raw objects; transition them to a colder tier after 90 days.
- Recovery method: `object-versioning-and-source-replay` — Restore a prior object generation or replay the immutable source.
- Recovery validation: `quarterly`

### Derived research data (`derived`)

- Classification: `internal`
- Accountable owner: `research`; operational steward: `platform`
- Writers: `job`; readers: `job`, `notebook`
- Retention policy: `retain-until-approved` — Retain current outputs until the research owner approves removal; keep superseded versions for at least 30 days.
- Recovery method: `object-versioning-or-recompute` — Restore a prior version when available, otherwise reproduce it from raw data and pinned code.
- Recovery validation: `quarterly-sample`

### Published research artifacts (`artifact`)

- Classification: `internal`
- Accountable owner: `research`; operational steward: `data_governance`
- Writers: `job`; readers: `job`, `notebook`
- Retention policy: `release-controlled` — Retain released artifacts until the research owner approves supersession or withdrawal.
- Recovery method: `object-versioning-and-rebuild` — Restore the released generation or rebuild it from pinned inputs and code.
- Recovery validation: `quarterly-sample`

### Temporary scratch data (`scratch`)

- Classification: `internal`
- Accountable owner: `platform`; operational steward: `research`
- Writers: `job`, `notebook`; readers: `job`, `notebook`
- Retention policy: `automatic-expiry` — Delete objects automatically after 14 days; scratch is never a system of record.
- Recovery method: `recompute` — Recreate from durable inputs; no restore guarantee applies.
- Recovery validation: `not-required`

### Quarantined source data (`quarantine`)

- Classification: `restricted`
- Accountable owner: `data_governance`; operational steward: `source_data`
- Writers: `feed`, `job`; readers: `job`, `notebook`
- Retention policy: `review-and-disposition` — Review within 30 days, then promote, retain under an approved exception, or delete through a reviewed change.
- Recovery method: `object-versioning-or-source-replay` — Recover a reviewed generation while an investigation is open; otherwise replay the source.
- Recovery validation: `quarterly-sample`

### Airflow task logs (`logs`)

- Classification: `internal`
- Accountable owner: `platform`; operational steward: `data_governance`
- Writers: `control`; readers: `control`
- Retention policy: `automatic-expiry` — Delete task logs automatically after 90 days.
- Recovery method: `rerun-or-operational-evidence` — Rerun the task when possible; preserve incident evidence separately when required.
- Recovery validation: `not-required`

### Backup and recovery evidence (`backup`)

- Classification: `restricted`
- Accountable owner: `platform`; operational steward: `data_governance`
- Writers: `recovery`; readers: None
- Retention policy: `retain-until-approved` — No automatic deletion; retention changes require recovery-policy approval.
- Recovery method: `versioned-backup-and-restore-drill` — Preserve immutable drill evidence and validate restoration through the quarterly staging exercise.
- Recovery validation: `quarterly`

## Changing ownership

1. Edit group contacts or class assignments in `config/data-ownership.toml`.
2. Obtain approval from the configured contract owner and change-approver groups.
3. Run `make ownership-render` and review both the manifest and generated document.
4. If readers, writers, locations, or prefixes changed, update and apply the matching Terraform IAM contract before data moves.
5. Run `make ownership-check`; CI rejects invalid references, overlapping prefixes, missing required classes, and stale generated documentation.

Group ownership does not itself grant cloud access. Access remains attached to the workload identities named above, so changing an accountable group cannot silently expand data-plane permissions.
